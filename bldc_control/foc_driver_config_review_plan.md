# FOC 驱动外设配置复查与整改逻辑

## 1. 文档目的

本文档基于当前工作区代码、`README.md` 指向的 DRV8301 数据手册和电机驱动原理图，记录 DRV8301、SPI、TIM1、ADC 以及 FOC 电流环之间需要修改或完善的逻辑。

本文档只描述整改方案，不直接修改源码。后续实现必须保留现有宏定义名称和原有宏定义描述；确有必要时只能新增同作用宏或别名。

## 2. 审查范围与依据

- `Core/Src/main.c`：外设启动顺序、PWM 启停、ADC 回调、故障处理。
- `Core/Src/spi.c`、`BSP_Driver/drv8301.c/.h`：DRV8301 SPI 协议和寄存器配置。
- `Core/Src/tim.c`：TIM1 互补 PWM、TIM1_CH4 ADC 触发、TIM2 周期任务。
- `Core/Src/adc.c`：ADC1 普通组、注入组和 DMA 配置。
- `Core/Src/gpio.c`：EN_GATE、DC_CAL、SPI CS 默认电平。
- `FOC_Driver/foc.c`、`FOC_Driver/foc_hal.c`、`FOC_Driver/lowpass_filter.c`：调制、电流校准和电流滤波。
- `README.md` 第 17~24 行指向的本地资料：

## 3. 当前复查结论

### 3.1 当前已经改善的项目

1. `spi.c` 当前为 16 位数据宽度、MSB first、CPOL 低、CPHA 2EDGE，符合 DRV8301 的 16 位 SPI 帧和 Mode 1 时序要求。
2. `gpio.c` 当前将 `EN_GATE` 和 `DC_CAL` 的初始输出设为低，优于此前上电即置高的状态。
3. `SPI2` 当前使用 PB12~PB15 软件片选和 SPI2 复用功能，软件内部连接一致；仍需按实际 PCB 网络复核。
4. TIM1 中心对齐模式、`ARR=5600`、168 MHz 定时器时钟对应 15 kHz PWM，计算正确。
5. ADC1 的 PA0~PA2 相电压、PA3~PA5 三相电流通道与当前软件通道号一致；ADC 时钟 21 MHz、12 位分辨率本身合理。
6. DRV8301 寄存器地址、读写位、状态位、6PWM、增益 10 等宏定义与数据手册基本一致。

### 3.2 当前仍然阻断 FOC 正常运行或存在安全风险的项目

| 优先级 | 项目 | 当前判断 |
| --- | --- | --- |
| P0 | TIM1_CH4 固定在 `PWM_PERIOD/2` 触发电流采样 | 采样时刻没有随三相占空比变化，不能保证低侧分流电阻导通，三相电流可能失真。 |
| P0 | 普通 ADC 连续扫描 + 3 点循环 DMA | 理论序列完成频率约 259 kHz，普通组回调会长期占用 CPU，并与电流环中断竞争。 |
| P0 | PWM、TIM2、ADC DMA 先启动，再使能并配置 DRV8301 | EN_GATE 虽已默认低，但驱动器使能后 PWM 已经在运行，启动状态仍不够原子和可控。 |
| P1 | `BLDC_StopOutput()` 先写 CCR=0，再拉低 EN_GATE | 可能在真正关断前形成短暂低侧导通状态。 |
| P1 | TIM1 Break 禁用，未形成硬件 nFAULT 快速关断链路 | 不能确认 MCU 是否能在硬件故障发生时立即关闭 PWM。 |
| P1 | DRV8301 读写错误返回值语义不统一 | `0` 同时表示合法零值和通信失败，状态寄存器 2、控制寄存器读取失败难以追踪。 |
| P1 | 电流环使用 5 ms 低通滤波器 | 15 kHz 控制周期下滤波系数约 0.9868，电流反馈带宽明显偏低，可能造成电流环滞后。 |

## 4. 必须修改的逻辑

### 4.1 ADC 注入采样时刻必须与 PWM 调制协同

涉及位置：`Core/Src/tim.c:70~99`、`Core/Src/main.c:250`、`Core/Src/adc.c:89~114`、`FOC_Driver/foc.c:70~91`。

当前 TIM1_CH4 是 `TIM_OCMODE_TIMING`，比较值在主函数中固定为 `PWM_PERIOD / 2`。FOC 输出三相占空比时，CH1~CH3 的 CCR 会持续变化，因此 CH4 与任何一个相的有效采样窗口没有固定关系。

整改逻辑：

1. 以三相当前 CCR 计算本周期可用的低侧导通窗口，而不是固定使用 ARR/2。
2. 采样事件建议放在中心对齐计数器经过峰值后的稳定区间，并预留：
   - PWM 死区和开关尖峰消隐时间；
   - DRV8301/LM2904 输出建立时间；
   - 三次 ADC 注入转换总时间。
3. 当前 ADC 时钟为 21 MHz，15 周期采样时每通道约 27 个 ADC 时钟，三通道约 3.86 us。采样窗口必须大于该时间再加模拟建立裕量。
4. 如果任一相占空比导致有效窗口不足，必须明确处理：限制最大/最小占空比、降低调制深度，或切换到两相采样并重构第三相电流；不能继续把无效样本直接送入 Clarke 变换。
5. CCR1~CCR4 的更新应在明确的 PWM 更新边界生效，避免 CPU 在周期中间写 CCR 造成采样点和占空比错位。CH4 是否启用预加载必须和更新策略一致。
6. ADC 触发源只保留一种表达：要么直接使用 `TIM1_CC4`，要么通过 TIM1 TRGO；当前同时配置 `TIM_TRGO_OC4REF` 和 ADC 直接 CC4 触发，容易造成维护误解。

验收条件：逻辑分析仪或示波器同时观察 TIM1_CH1~CH3、CH1N~CH3N、CH4 触发和 ADC 注入完成标志，在 10%、50%、90% 占空比以及正反转时均能确认采样位于有效低侧导通窗口内。

### 4.2 降低普通 ADC 组的无效中断负载

涉及位置：`Core/Src/adc.c:46~86`、`Core/Src/adc.c:151~172`、`Core/Src/main.c:436~450`。

当前普通组为软件启动、连续扫描、DMA 循环，三通道序列约 3.86 us 完成，DMA 完成回调理论上约 259 kHz。回调内还调用 `HAL_GetTick()`、浮点计算和低通滤波，不适合作为相电压监测路径。

整改逻辑：

1. 推荐将普通组改为低速定时触发，例如 1~2 kHz；每次触发完成 3 通道 DMA 序列。
2. 如果必须连续采样，则使用较大的 DMA 缓冲区和低频半传输/全传输回调，不在每个三点序列完成时执行浮点处理。
3. DMA2_Stream0 和 ADC 注入中断必须分级：电流环注入中断优先，普通电压监测 DMA 低优先级。
4. 普通电压监测和电流环反馈使用不同的数据路径。电流环不能读取普通组 DMA 数据作为实时电流。
5. 为 ADC/DMA 回调增加过载计数或最大执行时间统计，确认中断执行时间不超过对应采样周期。

验收条件：普通 ADC 回调频率、最大执行时间和 ADC 注入回调抖动均有实测记录；电流环不因普通组 DMA 中断出现连续丢触发或超时。

### 4.3 重排启动流程，保持驱动输出处于明确安全状态

涉及位置：`Core/Src/main.c:211~321`、`Core/Src/gpio.c:54~68`、`BSP_Driver/drv8301.c:503~565`。

当前 `EN_GATE/DC_CAL` 默认低已经改善，但主函数仍先启动六路 PWM、CH4、TIM2 和普通 ADC DMA，然后才拉高 EN_GATE 并配置 DRV8301。应改为显式状态流程：

```text
SAFE_IO
  -> 外设初始化，EN_GATE=0、DC_CAL=0、CCR1~CCR4=安全值
  -> TIM1 仅运行计数器/CH4 触发，不启动六路功率 PWM 输出
  -> EN_GATE=1，等待 DRV8301 tSPI_READY
  -> SPI 读取 Device ID、状态寄存器并写入配置
  -> 读回 CTRL1/CTRL2，确认配置一致
  -> 保持功率 PWM 未输出，执行电流零点校准
  -> 原子启动六路 PWM，执行电机对齐
  -> 启动 ADC 注入中断，进入 RUN
```

注意：零点校准当前使用外部 `TIM1_CC4` 触发，不能把“启动定时器/CH4”省略；否则 `HAL_ADCEx_InjectedStart()` 只会等待外部触发而超时。校准函数应明确检查定时器和 ADC 触发已经运行，或增加独立的软件触发校准路径。

### 4.4 统一停止和故障关断顺序

涉及位置：`Core/Src/main.c:143~161`、`Core/Src/main.c:360~366`。

整改逻辑：

1. 先禁止 DRV8301（EN_GATE 低）或先关闭 TIM1 主输出使能 MOE，再修改 CCR。
2. 再将 CCR1~CCR3 设为安全值，清除/冻结电流参考值和 PID 积分状态。
3. 设置故障锁存状态，停止电流环继续更新占空比。
4. 记录故障来源：DRV8301 硬件 nFAULT、SPI 通信错误、ADC 超时、传感器错误必须能区分。
5. `BLDC_FailAndStop()` 应先执行硬件关断，再写日志和进入 `Error_Handler()`，避免日志阻塞时仍保持功率级使能。
6. 启动失败和运行时故障使用同一个不可恢复关断路径，避免出现部分通道仍运行的状态。

## 5. DRV8301 驱动逻辑完善

### 5.1 SPI 传输层

当前 `spi.c` 的 16 位、Mode 1 配置方向正确。仍需完善：

1. `DRV8301_SPI_TransmitReceive()` 进入传输前检查 `DataSize=16BIT`，并保证 `Size=1` 与 `uint16_t` 缓冲区匹配。
2. `DRV8301_CS_DELAY()` 当前注释写成“最小 400 ns”，与数据手册中的片选建立/保持时间描述不一致；固定 NOP 也不能保证实际时间，应改为可解释、可测量的延时，并在波形上确认 CS、SCLK 的关系。
3. 传输结束应确认 SPI `BSY` 清零后再拉高 CS，避免最后一位尚未完全移出就结束帧。
4. 读操作校验 `F=0`、返回地址等于期望地址，并将通信错误与 DRV8301 真实 FAULT 分开记录。
5. 所有寄存器地址先限制为 `0x00~0x03`；写操作只允许 CTRL1/CTRL2，不能仅检查 `addr < CTRL1`。

### 5.2 读写 API 和故障语义

当前 `DRV8301_ReadStatus2()`、`ReadCtrl1()`、`ReadCtrl2()` 在失败时返回 0，而 0 也可能是合法寄存器值；`DRV8301_WriteReg()` 直接丢弃返回值。

建议逻辑：

- 底层函数统一返回 `0/-1` 或明确枚举状态，上层通过输出参数取得寄存器值；
- `ReadStatus1()` 的“通信失败按 FAULT 处理”可以保留，但必须同时设置通信错误标志；
- `ReadStatus2()` 失败不能伪装成 Device ID 为 0，应让初始化失败；
- `ConfigInit()` 除 CTRL1/CTRL2 读回外，还应校验 Device ID 和关键状态；
- `ClearFaults()` 每一步都检查结果，禁止读取失败后用 `ctrl1=0` 继续写回；
- 写寄存器的响应是上一帧响应，不能把当前写帧的有效性误认为已经确认；配置写入必须通过后续读回验证。
- `DRV8301_ConfigInit()` 返回的是项目自定义 `0/-1`，主函数不应使用 `HAL_OK` 表达式比较，避免把不同接口的状态码语义混在一起。

### 5.3 避免位域类型重解释

当前使用 `*(DRV8301_StatusReg1_t *)&status` 等方式把 `uint16_t` 重解释为位域结构。该方式依赖编译器位域布局和别名规则。

整改逻辑：

- 对外寄存器值统一保留为 `uint16_t`；
- 使用已有 `*_Pos`、`*_Msk` 宏读取字段；
- 如果确实需要结构体，使用 `memcpy` 并增加编译器/字节序约束；
- 不把位域结构体布局作为 SPI 协议格式。

## 6. DRV8301 参数完善逻辑

### 6.1 过流阈值

原理图为三相 `10 mΩ` 分流电阻，DRV8301 两路内置放大器增益为 10，第三相由 LM2904 外部放大。当前软件量程约为：

```text
电流换算系数 = 3.3 / 4096 / (10 × 0.01) ≈ 0.00806 A/count
零点中心约为 1.65 V，理论量程约 ±16.5 A
```

DRV8301 VDS 保护必须按照实际 MOSFET 热态 `RDS(on)` 计算：

```text
I_trip = OC_ADJ_SET 电压 / RDS(on, Tj)
```

当前 `0.250 V` 可能高于 ADC 和电机允许电流范围，不能仅凭宏名称确认正确。整改时需要记录目标峰值电流、MOSFET 热态 `RDS(on)`、允许短路时间和保护误触发裕量，再选择 `OC_ADJ_SET`。

### 6.2 栅极电流和死区

当前 DRV8301 使用 1.7 A 栅极峰值电流，原理图有 10 Ω 栅极电阻，TIM1 `DeadTime=100`。按 168 MHz 定时器时钟，TIM1 的 100 个死区计数约为 595 ns；DRV8301 的 DTC 外部电阻还会叠加内部死区。

整改逻辑：

- 首次上电用示波器确认 GH/GL 不重叠、VGS 上升沿不过冲、SH 节点无异常振铃；
- 以 MOSFET 栅极电荷、10 Ω 电阻、母线电压和开关损耗共同决定栅极峰值电流；
- 调试阶段不要依赖 `TIM_LOCKLEVEL_1` 进行运行时调参，最终参数确认后再锁定；
- 死区不能只按理论值确定，必须在最高母线电压和最高温度条件下验证。

## 7. ADC 与电流环完善逻辑

### 7.1 注入组采样

当前三路注入转换使用 ADC1_IN3~IN5，通道映射正确，但三路是顺序转换而不是同时采样。三路总转换时间约 3.86 us，电机电流变化较快时会产生相间时间偏差。

整改逻辑：

- 将采样点放在功率开关稳定后，并保证整个三通道转换期间信号有效；
- 用示波器测量 DRV8301 SO1/SO2、LM2904 输出的建立时间和 ADC 触发间隔；
- 记录每次注入转换是否完成，发生超时、过载或触发丢失时立即停止电流环；
- 零点校准时确保三相没有有效功率电流，校准成功后再清除 DC_CAL；
- 校准均值之外增加最大偏差或标准差判断，避免在开关噪声或电机未静止时把错误值写入偏置。

### 7.2 电流反馈滤波

当前电流环回调使用 `LOWPASS_FILTER_CalcWithDt()`，滤波时间常数为 5 ms，控制周期为 66.7 us：

```text
alpha = 0.005 / (0.005 + 0.0000667) ≈ 0.9868
```

这会明显降低电流环带宽。建议将“实时控制电流”和“监测显示电流”分开：

- FOC 电流环使用经过零点校准、必要限幅和采样有效性检查的实时值；
- 监测数据显示可以使用 5 ms 或更慢的低通；
- 最终滤波参数应结合电机电感、PWM 频率和期望电流环带宽重新整定。

### 7.3 ADC 比例和校准

原理图分压电阻为 34.8 kΩ 和 4.99 kΩ，实际分压比约 `7.974`，软件使用 8.0，比例误差约 0.33%。`ADC_RESOLUTION=4096.0f` 也会引入轻微比例误差。

整改逻辑：

- 保留现有宏名称和描述；
- 增加运行时或生产校准系数，而不是直接覆盖原有宏；
- 使用已知电压和已知电流分别校准相电压比例、三相电流零点和增益；
- 校准结果记录版本、范围和有效标志，避免把未校准数据当作工程量使用。

### 7.4 调制范围必须服务于电流采样

当前 `FOC_Driver/foc.c:50~91` 将电压限制为电源电压的一半后，仍直接生成 0~100% 的三相自然 SPWM 占空比，没有设置最小导通时间、最大占空比和采样窗口约束。仅限制 `Uq` 不能保证每个 PWM 周期都有足够的低侧分流采样时间。

整改逻辑：

- 将可用调制范围与 ADC 采样所需的最小窗口绑定；
- 当调制深度逼近 0% 或 100% 时，降低电压指令或进入明确的采样降级策略；
- 若采用两相采样重构第三相，必须同时增加采样有效标志和异常分支；
- 电流环输出限幅、PWM 占空比限幅和 CH4 采样点计算必须使用同一套边界参数，不能分别使用互不相关的常量。

当前 `FOC_TEST_STAGE_CURRENT` 使用 `iq_ref=0.10 A`，电流 PID 的积分项为 0，适合作为低风险 bring-up 初值，不应直接作为最终闭环参数。最终参数需要根据电机电感、反电动势和目标电流环带宽重新整定。

## 8. TIM1 与故障保护完善逻辑

### 8.1 PWM 输出状态

当前 CH1 的 `OCIdleState` 为 RESET，CH2/CH3 为 SET，三相空闲状态不一致。需要结合 DRV8301 输入有效电平、互补输出和 EN_GATE 关断策略确认；若无明确硬件理由，应统一三相空闲状态。

### 8.2 Break/nFAULT 链路

当前 `BreakState=TIM_BREAK_DISABLE`，代码中也没有 MCU nFAULT GPIO 或 TIM1 BKIN 配置。整改前必须先根据原理图确认 nFAULT 是否真正连接到 MCU 或 BKIN：

- 若有 BKIN 连接，按 nFAULT 的有效电平配置 Break 极性，并验证故障后 MOE 自动清零；
- 若没有 BKIN，至少确认 DRV8301 的硬件锁存关断有效，同时将 nFAULT 接入 MCU EXTI 或保留独立故障输入；
- 不能把 200 ms 一次的 SPI 轮询当作唯一的过流快速保护。

### 8.3 PWM GPIO 速度和死区

当前 PE8~PE14 的 GPIO 速度为 LOW。该设置不一定错误，但需要观察 DRV8301 PWM 输入边沿是否满足时序、是否存在过慢边沿和 EMI 问题。不能仅通过提高 GPIO 速度替代栅极死区和硬件波形验证。

## 9. 建议的实现顺序

1. 保持现有宏名称不变，先完成 DRV8301 SPI 传输状态、地址边界、错误返回和读回校验。
2. 完成安全启动/停止状态机，确保 EN_GATE、MOE、PWM 通道和 ADC 触发的顺序明确。
3. 重新设计 TIM1_CH4 电流采样点，并限制在可采样调制范围内。
4. 将普通 ADC 组改为低速触发或分块 DMA，降低 DMA 回调负载。
5. 分离实时电流反馈和监测滤波，重新整定电流环 PID 与滤波参数。
6. 根据实际 MOSFET 热态参数重新确定 DRV8301 过流阈值。
7. 最后通过示波器、逻辑分析仪和带限流电源进行上电验证。

## 10. 验收清单

### 静态与构建

- [ ] SPI 使用 16 位数据宽度和完整 16 个时钟，编译无类型/对齐警告。
- [ ] DRV8301 地址、返回地址、帧错误和通信错误均有明确处理。
- [ ] 所有 HAL 启动函数检查返回值，失败路径进入统一安全关断。
- [ ] ADC、DMA、TIM 中断优先级和回调执行时间有记录。
- [ ] 原有宏名称和原有宏定义描述未被修改。

### 无电机上电

- [ ] EN_GATE、DC_CAL 上电保持低电平。
- [ ] DRV8301 Device ID 正确，CTRL1/CTRL2 读回一致。
- [ ] 六路 PWM 未启动前，功率级无有效栅极驱动。
- [ ] nFAULT、nOCTW、BKIN/EXTI（若有）电平和故障路径正确。

### 带限流电源和示波器

- [ ] GH/GL 互补波形无重叠，死区在全电压、全温度范围满足要求。
- [ ] TIM1_CH4 触发位于有效采样窗口，三路 ADC 注入转换全部完成。
- [ ] 零电流时三相偏置稳定，已校准电流均值接近 0 A。
- [ ] 已知电流下三相增益一致，ADC 不提前饱和。
- [ ] 人为触发 DRV8301 过流/欠压/过温故障时，功率输出在硬件允许时间内关闭，软件能记录准确故障源。

## 11. 当前验证边界

本次为静态代码和配置审查，未进行 Keil 编译、逻辑分析仪测量、示波器测量或实际电机上电。涉及 SPI 引脚、nFAULT/BKIN 连接、MOSFET 热态 `RDS(on)`、栅极波形和 ADC 有效采样窗口的结论，必须在对应硬件版本上实测确认。
