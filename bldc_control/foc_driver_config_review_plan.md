## 1. 目标

在现有硬件和代码基础上，参考 SimpleFOC 的职责划分、传感器对齐、电流检测和 FOC 执行顺序，裁剪实现一套最小、清晰、可验证的有感无刷直流电机驱动：

```text
AS5600 获取转子机械角度
  -> 计算电角度
  -> 同步采样 U/V 两相电流，W 相由 KCL 推算
  -> Clarke/Park 变换
  -> id/iq 电流 PI
  -> 逆 Park/Clarke
  -> 三相 PWM
  -> DRV8301 驱动功率桥
```

本方案实现：

- AS5600 转子位置检测；
- 电角度计算和零位对齐；
- U/V 两相电流同步采样、零点校准和 dq 电流环；
- 三相电压采样及监控；
- DRV8301 初始化、使能、故障读取和六路 PWM 驱动；
- `id_ref=0`、`iq_ref` 控制的电流/转矩模式；
- 可选的速度环和位置环，通过编译宏级联在电流环之上；
- 运行必需的故障关断。

### 1.1 环路范围与默认配置

速度环、位置环属于本方案范围，但采用**默认关闭、显式开启**策略：

| 环路   | 是否实现 | 默认状态 | 开启前置条件                             |
| ------ | -------- | -------- | ---------------------------------------- |
| 电流环 | 是       | 开启     | 第 17 节第一~五步全部通过                |
| 速度环 | 是       | 关闭     | 电流环台架验收通过，且第 22 节整改项完成 |
| 位置环 | 是       | 关闭     | 速度环台架整定通过                       |

代码中通过 `USE_CURRENT_LOOP` / `USE_SPEED_LOOP` / `USE_POSITION_LOOP` 三个宏裁剪，详见第 20.1 节。文档全篇凡描述"当前运行路径"处，均以默认配置（仅电流环）为准；描述外环时明确标注"速度环模式"或"位置环模式"。

为避免把 SimpleFOC 的通用框架完整搬入本项目，本次明确不增加：

- 开环速度或开环位置运行模式；
- 无感反电势、滑模观测器或其他位置估算；
- 新增编码器、霍尔传感器或其他角度传感器；
- 新增母线电压采样硬件；
- 相电压闭环、反电势重构或在线电机参数辨识；
- MTPA、弱磁、前馈解耦等扩展控制；
- 完整移植 SimpleFOC 的 Arduino 类库和平台抽象；
- RTOS、动态内存、命令行配置或复杂参数管理；
- 自动识别所有电流 ADC 通道映射并在线改写配置；
- 为追求高速而增加角度预测器或更换通信接口；
- 速度前馈、加速度前馈、S 曲线或梯形规划等轨迹生成；
- 外环参数自动整定。

`FOC_Driver/foc_test.c` 当前同时承载两类性质完全不同的代码，必须分开处理：

- **运行路径**：`Foc_VelocityLoop()`、`Foc_PositionLoop()`，由 `USE_SPEED_LOOP` / `USE_POSITION_LOOP` 裁剪，是第 20.2 节串级链路的实现体。文件名 `foc_test` 已名不副实，重命名为 `foc_outer_loop.c/.h` 列入第 22.1 节整改项。
- **必须删除的历史调试代码**：`Foc_TestOpenloopVelocity()`（Uq 直接取 `voltage_limit` 满幅输出，无任何电流保护）、`Foc_TestCloseloopVelocity()` 与 `Foc_TestCloseloopAngle()`（PID 输出直接灌给 `FOC_SetTorque()`，绕过电流环和过流校验）。三者当前无任何调用点，但仍参与编译。在一个要带功率级上电的工程里保留绕过保护的入口没有任何收益，第 22.1 节列为必删项。

## 4. SimpleFOC 思路的裁剪映射

SimpleFOC 将电机控制分为 Driver、Sensor、CurrentSense 和 Motor。项目不照搬类结构，只保留相同职责边界。

### 4.1 Driver：DRV8301 与 TIM1

对应项目：

- `BSP_Driver/drv8301.c/.h`
- `Core/Src/tim.c`
- `FOC_Driver/foc.c` 中的 PWM 输出逻辑

保留职责：

1. 初始化 DRV8301 SPI 和控制寄存器；
2. 设置 6PWM 模式和电流放大器增益；
3. 控制 `EN_GATE`；
4. 启停 TIM1 主输出 MOE；
5. 将三相目标电压转换为 CCR1/CCR2/CCR3；
6. 更新 CH4 电流采样触发点；
7. 读取并上报 DRV8301 故障。

不增加通用 Driver 类、运行时 PWM 模式切换或多型号驱动适配。

### 4.2 Sensor：AS5600

对应项目：

- `BSP_Driver/as5600.c/.h`
- `BSP_Driver/hal_iic.c/.h`
- `FOC_Driver/foc_hal.c`

保留职责：

1. 读取 AS5600 12 位原始角度；
2. 转换为 `[0, 2π)` 单圈机械角；
3. 跨越 0/4095 时维护多圈位置，供位置环和监控使用；
4. 保存最近一次成功读取时间；
5. 提供读取是否有效；
6. 将机械角转换为 FOC 使用的电角度；
7. 速度环模式下提供机械角速度估算。

`AS5600_GetVelocity()` 的原始差分**不再直接进入控制链路**。速度环/位置环模式下，AS5600 只负责提供 1 kHz 的实测机械角作为观测器的修正量，速度与角度反馈一律取自第 22.3 节的跟踪观测器；量化推导见第 22.2 节。原始差分保留用于监控和观测器验收对比。仅电流环模式下不得依赖任何速度量。

### 4.3 CurrentSense：两相电流采样

对应项目：

- `Core/Src/adc.c`
- `FOC_Driver/foc_hal.c/.h`
- `Core/Src/main.c` 的 ADC 注入回调

保留职责：

1. PWM 关闭时执行 U/V 两相电流零点校准；
2. TIM1_CH4 同步触发 ADC 注入组；
3. 将 ADC 原始值转换为 U/V 相电流，W 相由 KCL 推算；
4. 应用固定的通道映射、方向符号和增益；
5. 检查 ADC 饱和、采样窗口和软件过流；
6. 把有效电流交给 FOC 电流环。

不实现 SimpleFOC 通用库中的多驱动、多 ADC 架构。由于本项目硬件固定，通道顺序和符号采用明确配置加台架验证，不做复杂的运行时自动重映射。

### 4.4 Motor：裁剪版 FOC 电流模式

对应项目：

- `FOC_Driver/foc.c/.h`
- `FOC_Driver/pid.c/.h`
- `FOC_Driver/foc_test.c/.h`（外环）
- `Core/Src/main.c`

电流环运行步骤：

```text
读取缓存电角度
  -> 检查电角度新鲜度
  -> 读取 U/V 电流并推算 W
  -> Clarke
  -> Park
  -> 软件过流校验
  -> id/iq PI
  -> dq 电压限幅
  -> 逆 Park
  -> 逆 Clarke
  -> 三相居中 PWM
```

控制目标固定为：

```text
id_ref = 0 A
-iq_limit <= iq_ref <= iq_limit
```

仅电流环模式下 `iq_ref` 是唯一电机控制输入，正负值分别产生正反方向转矩。开启外环后 `iq_ref` 由速度环输出，上层改为设置 `speed_ref` 或 `position_ref`。

## 6. 必须统一的物理定义

FOC 能否正确运行，首先取决于以下定义一致，而不是 PI 参数。

### 6.1 相定义与电流采样通道

实施前必须形成一张固定映射表：

| 软件定义 | PWM           | DRV8301/功率桥 | 电机相线 | 分流/反馈 | ADC              | 是否参与控制    |
| -------- | ------------- | -------------- | -------- | --------- | ---------------- | --------------- |
| U 相     | TIM1_CH1/CH1N | A 桥臂         | 电机 U   | IA_FB     | 注入 rank1 / PA3 | 是              |
| V 相     | TIM1_CH2/CH2N | B 桥臂         | 电机 V   | IB_FB     | 注入 rank2 / PA4 | 是              |
| W 相     | TIM1_CH3/CH3N | C 桥臂         | 电机 W   | IC_FB     | 注入 rank3 / PA5 | 否，由 KCL 推算 |

表中最终映射必须通过原理图、线束和小电流激励共同确认。

**W 相不参与控制的原因**：原理图上 A/B 相走 DRV8301 内置电流放大器，C 相走板载 LM2904。LM2904 为 3.3 V 单电源供电，静态工作点 1.65 V 已逼近其输出摆幅上限（`V+ - 1.5 V ≈ 1.8 V`），且不受 DRV8301 的 `DC_CAL` 短接控制，无法与 U/V 相同步做零点校准。实测其零点跨度约为 U/V 相的 4 倍，折算约 0.8 A 峰峰噪声，直接用作反馈会污染电流环。因此 W 相电流改由基尔霍夫电流定律推算：

```text
iw = -(iu + iv)
```

对应地，标定参数只保留两相：

```text
channel_u/channel_v
sign_u/sign_v
gain_u/gain_v
offset_u/offset_v
```

这些值使用固定配置，不增加运行时自动改线功能。W 相无独立的 `sign_w`/`gain_w`/`offset_w`，其精度完全由 U/V 相标定质量决定——这也意味着 **U/V 相的符号和增益标定必须在第 17 节第一步严格完成**，任一相标错都会同时污染 iw 和整个 Clarke 变换。

### 6.2 角度方向

统一公式：

```text
θe = normalize(sensor_direction × pole_pairs × θm - zero_electric_angle)
```

其中：

- `θm`：AS5600 单圈机械角；
- `sensor_direction`：`+1` 或 `-1`；
- `pole_pairs`：当前电机固定配置为 11；
- `zero_electric_angle`：启动对齐得到的零电角；
- `θe`：范围 `[0, 2π)` 的电角度。

极对数本次不做自动辨识。若更换电机，由配置修改并重新验证。

### 6.3 电流方向

规定从逆变桥流向电机绕组为相电流正方向，ADC 转换后的 U/V 电流必须符合这一约定。

现行极性已由实测反推确认为正：占空比 `[U 49.7% V 56.0% W 30.6%]` 对应的相电压 `[+1.02 +2.53 -3.56] V`，与 `sign=+1` 换算出的电流 `[+0.258 +0.798 -1.056] A` 三相逐个同向，等效相阻 3.2~4.0 Ω 一致。即"ADC 读数高于 offset"对应相电流为正。

**不得再把 `iu + iv + iw ≈ 0` 用作运行时诊断**：`iw` 由 `-(iu + iv)` 推算，三相和在数学上恒等于 0，该校验永远通过，不具备任何检错能力。通道、符号、增益错误只能通过第 17 节第一步的**离线单相激励标定**发现，运行时不再重复检查。

## 7. AS5600 最小实现

### 7.1 保留的数据

AS5600 状态最少包含：

```text
raw_angle               最近成功的 12 位角度
previous_raw_angle      上一次成功的 12 位角度，用于跨圈判定
mechanical_angle        最近成功的单圈机械角
full_angle              多圈机械位置，供位置环和监控
rotation_offset         累计圈数折算的角度偏置
last_success_tick       最近成功读取时间
velocity_previous_angle 上一次测速基准角
velocity_previous_tick  上一次测速基准时间
error_count             连续读取错误数
magnet_detected         初始化时磁体检测结果
valid                   当前数据是否有效
```

不增加复杂滤波器链、电机参数辨识或无感位置估算。速度估算的原始形式是定窗口差分，但**其量化精度不足以直接驱动速度环**——1 ms 窗口下 1 LSB = 1.534 rad/s，为速度参考满量程的 15.3%，推导见第 22.2 节。因此速度环模式下速度与角度反馈必须经第 22.3 节的**角度/速度跟踪观测器**。本节此前「不增加角度预测器、速度观测器」的约束据此**解除**：该约束与「实现速度环、位置环」的目标不可兼得，二者只能保留一个。

### 7.2 更新规则

1. TIM2 每 1 ms 只设置任务标志；
2. 前台任务调用一次 `AS5600_Update()`；
3. 读取成功后：
   - 更新原始角；
   - 处理 0/4095 跨圈；
   - 更新单圈角和多圈位置；
   - 更新最近成功时间；
   - 清连续错误并设置有效；
4. 读取失败后：
   - 不改写最近成功角度；
   - 连续错误计数加一；
   - 当前周期不发布新角度；
5. FOC 只使用最近成功角度，但必须检查数据年龄，判定阈值见第 12.1 节。

### 7.3 最小安全检查

保留以下检查即可：

- 初始化读取必须成功；
- 启动前确认 AS5600 检测到磁体；
- 运行中读取失败或角度数据超过允许时间未更新时关断；
- 对齐期间角度必须产生可辨识变化；
- 原始角不能出现超过当前最大允许转速的异常跳变。

不加入 AGC 趋势分析、磁场幅值统计或装配质量评估功能。

### 7.4 软件 I²C 修正范围

保留现有软件 I²C，不改成硬件 I²C。只做正确驱动 AS5600 所必需的修正：

1. SDA、SCL 使用开漏输出，高电平通过释放总线获得；
2. 初始化后总线保持空闲高电平；
3. ACK 等待有明确超时；
4. 读写失败能够返回错误；
5. 不在 ADC ISR 中执行 I²C；
6. 用逻辑分析仪确认时序和上升沿满足当前板级连接。

不额外实现 DMA、异步事务或通用 I²C 设备框架。

## 8. 传感器对齐

参考 SimpleFOC 的传感器对齐思路，但只保留本电机必需步骤。

### 8.1 对齐目的

对齐只解决两个参数：

```text
sensor_direction
zero_electric_angle
```

极对数固定使用 11，不在运行时搜索。

### 8.2 对齐步骤

1. 确认 DRV8301 已初始化，电流零点已校准；
2. 启动 ADC 注入采样和软件过流检查；
3. 使用受限对齐电压建立固定定子磁场；
4. 缓慢改变一小段命令电角度，读取 AS5600 机械角变化；
5. 根据机械角变化正负确定 `sensor_direction`；
6. 如果机械角变化小于阈值，则判定电机未运动或传感器异常，立即退出；
7. 将转子稳定锁定到已知电角位置；
8. 读取机械角并计算 `zero_electric_angle`；
9. 将对齐电压降为零；
10. 清空 id/iq PI 状态，再进入运行态。

不实现长距离往返扫描、极对数自动估算或校准参数永久存储。

### 8.3 对齐限制

独立设置：

```text
alignment_voltage
alignment_current_limit
alignment_timeout
```

这三个量只用于防止对齐阶段过流或长时间堵转，不作为新的控制功能。

## 9. 电流采样最小实现

### 9.1 零点校准

保留当前 DC_CAL 方式：

1. MOE 关闭、功率 PWM 不输出；
2. DRV8301 使能并进入 DC_CAL；
3. TIM1_CH4 继续产生 ADC 注入触发；
4. 采集约 200 组样本；
5. 分别计算 U/V 两相 offset；
6. 检查样本跨度（`≤ 64` counts）和是否靠近 ADC 电源轨（余量 `≥ 16` counts）；
7. 校准失败不得使能功率输出。

W 相不做零点校准：其 LM2904 通道不受 `DC_CAL` 控制，校准动作对它无效。

### 9.2 电流转换

U/V 两相统一为：

```text
phase_current = (raw - offset) × adc_factor × gain × sign
```

其中 channel、gain 和 sign 使用固定配置。W 相不经 ADC 换算，直接由 `iw = -(iu + iv)` 得到。

### 9.3 PWM 同步采样

继续使用 TIM1_CH4 触发注入组，不改变现有外设方案。

必须确认：

- CH4 位于 U/V 相低侧电流均可测的稳定窗口；
- 采样点避开死区和开关尖峰；
- 注入通道完整转换结束前采样窗口仍有效；
- CCR1~CCR4 在同一更新边界生效；
- 一个 PWM 周期只产生一次期望的电流环回调。

当前动态 CH4 计算逻辑可以保留，但必须用示波器或调试 GPIO 验证。

### 9.4 电流有效性检查

ADC ISR 只保留必要检查：

1. U/V 两路原始 ADC 未接近 0/满量程（有效区间 `[16, 4079]`）；
2. 电流 offset 已校准；
3. 当前 PWM 采样窗口有效；
4. 任一相电流（含推算的 W 相）未超过软件绝对限值；
5. 注入 ADC 回调未停止。

任一检查失败，立即关闭 MOE 和 EN_GATE，并锁存故障。

**已废止的检查**：原第 5 项 `iu+iv+iw` 容差校验随两相采样方案一并删除，理由见第 6.3 节——该式在 KCL 推算下恒成立，保留它只会制造"已有诊断"的错觉。原始 ADC 饱和检查（第 1 项）承担了它原本想覆盖的一部分失效模式，必须实际存在于 ISR 中，不能只写在文档里。

### 9.5 电流滤波

15 kHz FOC 电流反馈不使用低通滤波器。

现有低通只用于两处，均不进入 Clarke/Park 和 PI：

- 监控数据显示降噪（1 kHz 抽取后滤波）；
- 速度环模式下的速度反馈滤波（见第 22.2 节）。

## 10. 三相电压采样的裁剪用途

三相电压采样不是当前有感电流 FOC 的控制反馈，因此只保留：

1. TIM2 TRGO 以约 1 kHz 触发 ADC 普通组；

- 转子位置估算；

电压采样异常只记录监控状态，不作为高频电流环输入。是否触发关断沿用现有项目策略，不新增复杂判定。

## 12. 裁剪版 FOC 算法

### 12.1 电角度

AS5600 更新在 1 ms 前台任务中执行，成功后更新缓存电角度：

```text
cached_angle_el = normalize(direction × pp × angle_m - zero_el)
```

ADC 电流 ISR 不读取 I²C，只使用缓存电角度。

为避免使用过期角度，ISR 或进入 ISR 前的共享状态必须判断：

```text
current_time - last_success_time <= sensor_max_age_ms
```

**`sensor_max_age_ms` 的取值不是可随意放宽的容错参数，而是安全边界。** 陈旧角度经 Park 变换后直接决定转矩方向，误差换算关系为：

```text
Δθe = sensor_direction × pp × ω_m × Δt
```

当前 `pp=11`、目标机械速度 5 rad/s 时：

| 数据年龄 | 电角误差   | 后果                                   |
| -------- | ---------- | -------------------------------------- |
| 1 ms     | 约 3.15°  | 可接受，转矩损失 < 0.2%                |
| 3 ms     | 约 9.5°   | 转矩损失约 1.4%，仍可控                |
| 5 ms     | 约 15.8°  | 转矩损失约 4%，为可接受上限            |
| 50 ms    | 约 157.6° | 转矩分量近乎反向，电流环正反馈直至过流 |

因此规定：

```text
sensor_max_age_ms = 3 ~ 5 ms
```

即允许连续丢 2~4 拍 AS5600 读取，超出即判定传感器失效并关断。**禁止把该值设为 10 ms 以上**——那样电角误差会超过 30°，过流保护会先于角度保护动作，等于用"炸机保护"替代"逻辑保护"，故障现场也无法区分是标定错误还是传感器超时。

> ⚠ **当前代码违反本约束**：`Core/Src/main.c` 的 `FOC_SENSOR_MAX_AGE_MS` 为 `50U`，并在 `FOC_Closeloop_Init()` 之后覆盖了 `FOC_Driver/foc.c` 中 `FOC_DEFAULT_SENSOR_AGE = 5U` 的正确默认值。50 ms 正是上表中「转矩分量近乎反向」的那一行。列为第 22.1 节 P0 整改项。

开启角度/速度跟踪观测器（第 22.3 节）后，本阈值的含义不变但作用对象变化：观测器在丢拍期间按 `ω̂` 外推角度，`sensor_max_age_ms` 转为**观测器允许自由外推的最长时间**。外推误差同样按上表增长（外推误差来自 `ω̂` 的估计误差而非零速假设，实际增长更慢），因此阈值可维持 3~5 ms 不放宽。**提速的正确前提是缩短 AS5600 更新周期，不是容忍更旧的角度，也不是依赖观测器无限外推。**

### 12.2 Clarke 变换

由 U/V 两相实测电流和推算的 W 相变换为 α/β：

```text
iw      = -(iu + iv)
i_alpha = 2/3 × (iu - iv/2 - iw/2)
i_beta  = 1/√3 × (iv - iw)
```

代码保持三电流入参形式（`FOC_Clarke(iu, iv, iw)`），W 相在 `FOC_Get_Calibrated_Current()` 中推算后传入，Clarke 本身不感知采样方式。

### 12.3 Park 变换

```text
id =  i_alpha × cos(θe) + i_beta × sin(θe)
iq = -i_alpha × sin(θe) + i_beta × cos(θe)
```

### 12.4 电流 PI

控制误差：

```text
error_d = 0 - id
error_q = iq_ref - iq
```

输出：

```text
Ud = PI_d(error_d)
Uq = PI_q(error_q)
```

裁剪要求：

- D 固定为 0；
- 电流环使用固定 `dt=1/15000 s`，不读取 `HAL_GetTick()`；
- 初始从低 P、低 I 开始；
- PI 输出进行简单限幅；
- 输出饱和时停止继续向同方向积分，采用条件积分即可；
- 抗饱和采用**冻结积分**而非回算：本项目 `P=4`、`limit=4`，误差 1 A 时 P 项单独即吃满限幅，回算会把积分打到 0 甚至反向，误差回落后输出符号会翻转；
- 不增加解耦、反电势前馈或自动整定。

电流环 `I` 必须为非零值，`I=0` 只是 P 控制，存在与负载成正比的稳态电流误差。

### 12.5 逆变换与调制

使用同一组 `sin(θe)`、`cos(θe)` 完成逆 Park：

```text
U_alpha = Ud × cos(θe) - Uq × sin(θe)
U_beta  = Ud × sin(θe) + Uq × cos(θe)
```

再通过逆 Clarke 得到三相电压，并加入半母线偏置生成 PWM。

保留当前三相共模居中和占空比范围限制，不新增扇区式 SVPWM。调制必须优先满足低侧电流采样窗口。

### 12.6 运行接口

上层接口按控制模式暴露，详见第 20.3 节：

```text
BLDC_SetIqReference(float iq_ref)          仅电流环模式
BLDC_SetSpeedReference(float rad_s)        速度环模式
BLDC_SetPositionReference(float rad)       位置环模式
BLDC_Stop()
BLDC_GetMonitorData()
BLDC_GetFault()
```

实际命名可保持当前接口风格，不要求为此重构所有文件。未启用的环路对应接口由编译宏裁剪，调用时返回 `-1`。

## 13. 调度与运行流程

### 13.1 15 kHz ADC 注入 ISR

只执行：

```text
读取三相 ADC
  -> ADC/电流/采样窗口检查
  -> 电流转换
  -> Clarke/Park
  -> id/iq PI
  -> 逆变换和 PWM 更新
```

禁止执行：

- AS5600 I²C；
- SPI 故障轮询；
- 电压普通组处理；
- 日志输出；
- HAL_Delay；
- 速度或位置控制。

### 13.2 1 ms 前台任务

执行内容按控制模式裁剪。**仅电流环模式**（默认配置）：

```text
AS5600_Update
  -> 检查传感器有效性和数据年龄
  -> 更新缓存机械角/电角
  -> 更新 iq_ref 斜坡（如保留）
```

**速度环 / 位置环模式**在其后追加外环调度，顺序见第 23.3 节：

```text
（tick 开头）位置环 -> speed_ref -> 速度环 -> iq_ref
  -> AS5600_Update（阻塞软件 I²C，约 210~235 µs）
  -> 观测器 1 kHz 修正
```

注意外环排在 `AS5600_Update` **之前**、使用上一拍的观测器输出，这是刻意的：软件 I²C 的阻塞时间和失败重试都会污染外环的执行时刻，把外环钉在 tick 开头才能让 `dt = 1 ms` 这个固定值成立。当前代码把外环放在 `AS5600_Update` 成功之后（`Core/Src/main.c` 的 1 ms 任务），属于第 22.1 节整改项。

本节此前「不执行速度环和位置环」的表述与第 20.2 节直接矛盾，已订正。ADC 电流 ISR 内**始终**禁止执行速度或位置控制，该约束不变，见第 13.1 节。

### 13.3 普通 ADC 回调

只完成三相电压换算、低通和监控数据更新。

### 13.4 低频故障任务

## 14. 最小启动状态

不建立复杂状态机，只保留五个明确状态：

```text

  -> INIT
  -> ALIGN
  -> RUN
  -> FAULT
```

- MOE 关闭；
- EN_GATE 低；
- `iq_ref=0`；

- 1 ms 更新 AS5600；
- 1 kHz 更新三相电压监控；

### 14.5 FAULT

- 拉低 EN_GATE；
- 清参考和 PI；

## 20. 最终裁剪结论

本项目按 SimpleFOC 思路只保留四个必要组成：

```text
DRV8301/TIM1 Driver
AS5600 Sensor
ADC CurrentSense
Current-mode FOC Motor
```

最终运行路径固定为：

```text
1 ms：AS5600 更新机械角和缓存电角
15 kHz：同步电流采样 -> Clarke/Park -> id/iq PI -> PWM
1 kHz：三相电压采样，仅监控
低频：DRV8301 状态检查
```

最终功能固定为：

- AS5600 有感；
- 三相电流闭环；
- `id_ref=0`；
- `iq_ref` 转矩控制；
- 速度闭环；
- 位置、速度、电流三级串级闭环；
- 三相电压监控；
- DRV8301 六路 PWM 驱动和故障关断。

### 20.1 环路宏配置

环路功能通过 `Core/Inc/main.h` 中的编译宏选择：

```c
#define USE_CURRENT_LOOP  1
#define USE_SPEED_LOOP    0
#define USE_POSITION_LOOP 0
```

| 控制模式 | `USE_CURRENT_LOOP` | `USE_SPEED_LOOP` | `USE_POSITION_LOOP` |
| -------- | -------------------- | ------------------ | --------------------- |
| 电流环   | 1                    | 0                  | 0                     |
| 速度环   | 1                    | 1                  | 0                     |
| 位置环   | 1                    | 1                  | 1                     |

宏配置遵循以下依赖关系：

- 三个宏只能定义为 `0` 或 `1`；
- 速度环必须依赖电流环，即 `USE_SPEED_LOOP=1` 时必须设置 `USE_CURRENT_LOOP=1`；
- 位置环必须依赖速度环，即 `USE_POSITION_LOOP=1` 时必须设置 `USE_SPEED_LOOP=1`；
- 不合法的组合通过 `#error` 在编译阶段终止构建；
- 默认配置为仅启用电流环，避免外环参数未完成台架整定时电机意外运动；
- `0/0/0` 可以用于代码裁剪和构建检查，但不作为正常电机控制模式。

### 20.2 控制环运行链路

启用位置环时，控制器按以下三级串级链路运行：

```text
position_ref（累计机械角 rad，已按 sensor_direction 修正）
    -> 位置 P（输出限幅即 speed_ref 限幅）
    -> speed_ref（rad/s，限制为 +/-10 rad/s）
    -> 速度 PI
    -> iq_ref（A，限制见第 20.3 节）
    -> id/iq 电流 PI，id_ref 固定为 0 A
    -> 逆 Park / 逆 Clarke / 三相共模居中调制
```

末级是**三相共模居中**（min-max 居中偏置），不是扇区式 SVPWM，见第 12.5 节。原文写作「SVPWM」不准确，已订正。

各环路调度周期如下：

| 环路       | 执行位置                       | 周期/频率         | 输入                              | 输出                   |
| ---------- | ------------------------------ | ----------------- | --------------------------------- | ---------------------- |
| 位置环     | 主循环 1 ms tick**开头** | 1 ms / 1 kHz      | 观测器`θ̂_mech`（多圈）       | `speed_ref`          |
| 速度环     | 紧随位置环，同一 tick          | 1 ms / 1 kHz      | 观测器`ω̂`                    | `iq_ref`             |
| 观测器修正 | `AS5600_Update()` 成功后     | 1 ms / 1 kHz      | AS5600 实测机械角                 | 修正`θ̂`、`ω̂` |
| 观测器外推 | ADC 注入 ISR 开头              | 66.7 µs / 15 kHz | `ω̂`                          | `θ̂` → 电角度     |
| 电流环     | ADC 注入转换完成中断           | 15 kHz            | `iq_ref`、U/V 电流、`θ̂_el` | `ud/uq`、下周期 PWM  |

三点必须写死：

1. **外环排在 `AS5600_Update()` 之前**，理由见第 13.2 节——软件 I²C 阻塞 210~235 µs，把外环放在它后面会让「dt = 1 ms」这个固定值失真。
2. **位置环与速度环同拍执行、无分频**，因此两级之间的带宽分离**只能靠参数实现**，量化约束见第 23.1 节。这不是缺陷，但必须显式约束，否则串级会自激。
3. **速度与位置反馈都来自观测器，不是 AS5600 原始差分**。原始差分量化为 1.534 rad/s（第 22.2 节），直接进 PID 无法整定。原文「速度反馈由 AS5600 计算，经一阶低通滤波后进入速度 PID」是当前代码的实现，也是速度环整定不出来的根因，已订正。

位置反馈使用观测器维护的多圈累计机械角，因此位置参考值允许跨越多圈。

### 20.3 参考值接口

对外控制接口声明在 `Core/Inc/main.h`：

```c
int BLDC_SetIqReference(float reference);
int BLDC_SetSpeedReference(float reference);
int BLDC_SetPositionReference(float reference);
```

| 接口                            | 编译/使用条件          | 单位           | 处理方式                                                                      |
| ------------------------------- | ---------------------- | -------------- | ----------------------------------------------------------------------------- |
| `BLDC_SetIqReference()`       | 仅电流环模式           | A              | 限幅`±FOC_IQ_REF_LIMIT`（设计值 `0.30 A`，代码现值 `0.53 A`，见 22.1） |
| `BLDC_SetSpeedReference()`    | 速度环开启且位置环关闭 | rad/s          | 限幅`±10 rad/s`                                                            |
| `BLDC_SetPositionReference()` | 位置环开启             | 累计机械角 rad | 多圈位置目标，**必须限幅**（当前代码只做 NaN 检查，见 22.1）            |

三个 Setter 的公共约束：NaN 拒绝 → 对称限幅 → 临界区内校验 `state == RUN && !fault_latched` → 写入。位置参考虽然物理上允许多圈，但仍需限幅到机械可达范围，否则一个错误的大数会让位置环持续输出满幅 `speed_ref`，只靠速度环限幅兜底，不符合「每级都自带边界」的原则。

接口仅在电机处于 `BLDC_STATE_RUN` 且没有锁存故障时接受新参考值。返回 `0` 表示设置成功，返回 `-1` 表示当前控制模式或运行状态不允许设置。主循环更新参考值时使用临界区，与 15 kHz 电流中断之间不发生数据竞争。

### 20.4 启动、停止和故障行为

- 仅电流环模式启动后使用 `FOC_INITIAL_IQ_REF`（设计值 `0.10 A`，代码现值 `0.25 A`，见 22.1）；
- **速度环模式启动目标必须为 `0 rad/s`**，由上层显式设置后才允许运动。代码现值为 `speed_ref = 5.0f`（初值与 ALIGN 之后的赋值各一处，后者还没有临界区保护），意味着一进 RUN 电机就自己转起来。这是安全相关的偏差，列为 22.1 P1；
- 位置环模式将启动目标初始化为**当前观测器位置**，避免进入闭环时产生位置跳变；
- 进入 RUN 之前必须复位全部已启用环路的 PID 与观测器状态，否则 ALIGN 阶段积累的积分会在闭环瞬间释放；
- `BLDC_Stop()` 或故障关断时，将 `iq_ref` 清零并复位所有已启用环路的 PID；
- 传感器更新失败、ADC 异常、相电流越限、采样窗口无效或 DRV8301 故障时，仍沿用统一锁存故障和硬件关断路径；
- 故障锁存后无恢复路径（`bldc_fault_latched` 全工程只有置位、无清零），只能复位重启。这是刻意选择，不是遗漏——但要写进对外文档，否则上位机会以为存在 clear-fault 接口。

## 21. TIM1 与 ADC 配置审查（2026-08-11 复审）

本节对 `Core/Src/tim.c` 和 `Core/Src/adc.c` 的当前配置进行逐项审查，确认是否满足第 3、9、13 节的方案要求。

> **本节相对 2026-08-06 版的变更**：原版四项结论已失效——`RepetitionCounter` 已修复、CH4 实为 TOGGLE 而非 TIMING、注入组已改为 2 通道、采样时间已由 15 周期改为 480 周期。原第 21.4 节对低侧采样窗口位置的判断（「位于谷值附近」）是**错的**，本次订正。

### 21.1 时钟基础计算

```text
MCU：STM32F407VET6，SYSCLK = HCLK = 168 MHz
APB2 预分频 = 2  -> PCLK2 = 84 MHz -> TIM1 计时钟 = 168 MHz
APB1 预分频 = 4  -> PCLK1 = 42 MHz -> TIM2 计时钟 = 84 MHz
ADC 时钟 = PCLK2 / 4 = 84 / 4 = 21 MHz（F407 上限 36 MHz，合规）

TIM1 tick = 1 / 168 MHz = 5.952 ns
PWM_PERIOD(ARR) = 168e6 / (2 × 15000 × 1) = 5600
PWM 周期 = 2 × 5600 tick = 11200 tick = 66.667 µs = 15.000 kHz
TIM2 周期 = 84e6 / 84 / 1000 = 1.000 kHz = 1.000 ms
```

### 21.2 TIM1 配置审查

| 配置项                      | 当前值                              | 方案要求           | 结论                |
| --------------------------- | ----------------------------------- | ------------------ | ------------------- |
| CounterMode                 | CENTERALIGNED1                      | 中心对齐           | ✓                  |
| PWM 频率                    | 15.000 kHz                          | 15 kHz             | ✓                  |
| CH1/2/3 模式                | PWM1，OCPolarity/OCNPolarity = HIGH | 互补 PWM 输出      | ✓                  |
| **RepetitionCounter** | **1**                         | 1                  | ✓**已修复**  |
| CH1~CH4 预加载              | 全部启用（CH4 重复使能两次，无害）  | CCR 同边界生效     | ✓                  |
| ARPE                        | ENABLE                              | 保持稳定 ARR       | ✓                  |
| 死区时间                    | DTG=100 → 100 × 5.952 ns = 595 ns | 需台架确认         | 待定                |
| TRGO 源                     | OC4REF                              | 驱动 ADC 注入      | ✓                  |
| **CH4 模式**          | **TOGGLE**                    | 见下               | **需改 PWM2** |
| BKIN                        | DISABLE                             | 硬件无 nFAULT 连线 | ✓ 但见 22.5        |
| OSSR / OSSI                 | DISABLE                             | —                 | 见下                |

原版表格中「CH4 模式 = TIMING（仅比较触发）✓」是错的，有两层问题：

1. **事实不符**：代码为 `TIM_OCMODE_TOGGLE`。
2. **原描述若照做就是死的**：TIMING（Frozen）模式下 OC4REF 恒为 0，而 TRGO = OC4REF，ADC 注入将**永远收不到触发沿**。任何人照文档去「修正」CH4 都会把电流环彻底关掉。

**TOGGLE 模式的实际隐患**：OC4REF 在每次 CCR4 匹配时翻转。中心对齐每个 PWM 周期有两次匹配（上计数一次、下计数一次），因此 TRGO 每周期恰好一个上升沿——**频率是对的**。但上升沿落在上计数匹配点还是下计数匹配点，取决于 OC4REF 的初始电平，而两者关于峰值镜像对称。`FOC_SetPwm()` 的 CCR4 计算假设的是**上计数匹配点**；相位一旦翻转，实际采样时刻变成 `2·ARR − CCR4`，可能落到低侧关断之后。计数器重置、`EGR=UG` 强制加载或 CCR4 大幅跳变都可能触发相位翻转。

**推荐配置**：

```c
sConfigOC.OCMode = TIM_OCMODE_PWM2;   /* OC4REF = 1 当 CNT > CCR4 */
```

PWM2 下 OC4REF 在上计数越过 CCR4 时唯一一次由 0 变 1，下计数越过时回 0，**每周期一个位置确定的上升沿**，与 `FOC_SetPwm()` 的假设严格一致。

**OSSR / OSSI = DISABLE 的含义**：MOE = 0 时六路输出进入高阻，而非驱动到 idle 电平。DRV8301 的 INHx/INLx 依靠器件内部下拉保持关断。这是可接受的（`EN_GATE = 0` 才是主保护），但**安全性依赖第三方器件的内部电阻**，必须在台架上实测确认 MOE 关闭后 INHx/INLx 电平，并写入验收清单。

| 读取方式           | `HAL_ADCEx_InjectedGetValue` 轮询 JDRx | —                  | ✓              |
| **采样时间** | **480 cycles**                     | **15 cycles** | **✗ P0** |

**P0：注入采样时间 480 周期，采样窗口保护失效**

```text
单通道耗时 = (480 + 12) / 21 MHz = 23.43 µs
两通道串行 = 2 × 492 / 21 MHz = 46.86 µs
折算 TIM1 ticks = 46.86 µs × 168 MHz = 7873 ticks

main.h 中 PWM_ADC_SEQUENCE_TICKS = 648U（按「3 通道 × 15 周期」的旧配置计算）
7873 / 648 = 12.1 倍
```

三重后果：

1. **窗口保护形同虚设**。`FOC_SetPwm()` 用 `trigger_earliest = max_compare + PWM_ADC_SEQUENCE_TICKS + PWM_ADC_END_MARGIN_TICKS` 判断本周期采样是否可行，少算 7225 tick，`next_sample_valid` 恒为 1。
2. **采样孔径装不进导通窗口**。低侧共同导通窗口 = `2 × (ARR − max_compare)` tick。占空比取上限 `PWM_MAX_COMPARE = 4652` 时窗口只有 1896 tick = 11.3 µs，**连一个通道的 22.86 µs 都装不下**；即使 50% 占空比（窗口 33.3 µs），两通道串行的 46.86 µs 仍然溢出。
3. **U/V 不是同步采样**。两个通道的采样时刻相差 22.86 µs ≈ 1/3 个 PWM 周期，Clarke 变换「三相同一时刻」的前提被破坏，`i_alpha`/`i_beta` 从根上就是错的。

另外注入转换占满 66.7 µs 周期的 70%，ISR 触发时刻严重后移，`FOC_CommitPwmUpdate()` 与 UEV 的相对时序也不再成立。

**修法**：

```c
sConfigInjected.InjectedSamplingTime = ADC_SAMPLETIME_15CYCLES;   /* adc.c */
#define PWM_ADC_SEQUENCE_TICKS  432U    /* main.h：2 × (15+12) / 21MHz × 168MHz */
```

修正后序列耗时 2.571 µs（432 tick），单通道孔径 0.714 µs（120 tick），两相时差 1.286 µs（周期的 1.9%）。H2 接口上已有 R48~R50 + 2.2 nF 的 RC 网络在引脚处提供电荷储备，ADC 采样电容（约 4 pF）的取电扰动可忽略，15 周期足够；480 周期是对源阻抗的过度补偿，代价是把整个电流采样方案毁掉。

> 若后续要彻底消除两相时差，可改用 ADC1 + ADC2 注入双同步模式（PA3 = ADC1_IN3、PA4 = ADC2_IN4，F407 的 ADC2 当前空闲，无需改硬件）。本次不做，列为第 22.6 节可选增强。

**普通组（电压监控，非 FOC 路径）：**

| 配置项                       | 当前值                    | 方案要求            | 结论         |
| ---------------------------- | ------------------------- | ------------------- | ------------ |
| 触发源                       | T2_TRGO 上升沿            | TIM2 TRGO 1 kHz     | ✓           |
| 通道数 / 映射                | 3，CH0/1/2 → PA0/PA1/PA2 | 三相端电压          | ✓           |
| DMA 模式 / 宽度              | CIRCULAR / HALFWORD       | 持续采样、12 位对齐 | ✓           |

`ContinuousConvMode = ENABLE` 使普通组在首次 T2_TRGO 之后**自由连续转换**，不再受 1 kHz 触发控制：

```text
序列耗时 = 3 × (480 + 12) / 21 MHz = 70.3 µs -> 实际刷新约 14.2 kHz
```

后果有三个：DMA 持续搬运；普通组被 15 kHz 注入组反复抢占、恢复后重启当前通道，数据有效性存疑；`HAL_ADC_ConvCpltCallback` 中传给低通滤波器的 `dt` 硬编码为 `1/MONITOR_SAMPLE_FREQ = 1 ms`，与实际 70 µs 差 14 倍，监控滤波的时间常数完全不是设计值。改 `DISABLE` 即可让 TIM2 恢复对采样节拍的控制。

### 21.4 ADC 采样窗口有效性分析

> **本节整节订正。** 原版结论「三路低侧管同时导通的窗口位于 CNT 接近谷值（0）附近」是错的。

STM32 PWM 模式 1 的定义（RM0090）：上计数时 `CNT < CCRx` 为有效，下计数时 `CNT > CCRx` 为无效——合并即 **`OCxREF = 1 ⟺ CNT < CCRx`，与计数方向无关**。配合 `OCPolarity = HIGH`、`OCNPolarity = HIGH`：

```text
CNT ≈ 0（谷值）   : OCxREF = 1 -> 高侧导通，低侧关断
CNT ≈ ARR（峰值） : OCxREF = 0 -> 高侧关断，低侧导通
```

因此**低侧共同导通窗口居中于峰值**，跨度为 `2 × (ARR − max(CCR1,CCR2,CCR3))` tick。分流电阻接在低侧 MOSFET 源极到地（原理图 Q3/Q5/Q7 下方），只有低侧导通时才有电流流过分流电阻，所以 ADC 必须在这个窗口内采样。

代码是对的，宏命名也是对的——`PWM_ADC_PEAK_BLANKING_TICKS`（峰值消隐）、`trigger_earliest = max_compare + …`（等所有高侧关断后才触发）都指向峰值窗口。**错的只有原文档的这句话**，而按它去实施会把触发点挪到谷值，采到的是高侧导通期间流过分流电阻的零电流。

当前窗口约束宏（`main.h`）：

```c
PWM_ADC_PEAK_BLANKING_TICKS = 200                    /* 1.19 µs 消隐 */
PWM_MIN_COMPARE             = 200                    /* 最小占空比 3.57% */
PWM_MAX_COMPARE             = 5600 - 648 - 100 - 200 = 4652   /* 最大占空比 83.1% */
PWM_ADC_TRIGGER_LATEST      = 5600 - 200 = 5400
```

CCR4 由 `FOC_SetPwm()` 每周期动态计算，取 `[trigger_earliest, PWM_ADC_TRIGGER_LATEST]` 的中点。该公式在 `PWM_ADC_SEQUENCE_TICKS = 648` 时**恰好安全但并非按约束构造**：最坏情况 `max_compare = 4652` 时 CCR4 = 5400，转换在下计数的 CNT = 5152 处结束，仍大于 4652，余量 500 tick。但代码从未显式校验「转换结束点仍在低侧窗口内」这个真正的约束：

```text
正确约束：trigger + SEQUENCE_TICKS ≤ 2·ARR − max_compare − END_MARGIN
现有实现：trigger ≥ max_compare + SEQUENCE_TICKS + END_MARGIN，且 trigger ≤ ARR − BLANKING
```

现有实现把转换时长加在**下界**上而不是从**上界**扣除，方向反了，靠 `PWM_ADC_TRIGGER_LATEST` 的保守取值意外兜住。改采样时间为 15 周期（`SEQUENCE_TICKS = 432`）后余量更大，但建议一并把校验式改成上面的正确形式，否则下次改动 ADC 配置又会静默失效——这正是本次 480 周期问题的成因。

**台架必须实测**：调试 GPIO 在 ADC 注入 ISR 入口翻转，与 CH4 输出引脚（PE14，已引出）、任一低侧栅极信号同时抓波，确认触发沿落在低侧共同导通区间的中部。这一项在第 18.2 节尚未勾选，且是电流环所有后续工作的前提。

### 22.2 AS5600 测速的量化约束

这是速度环能否成立的决定性约束，也是第 4.2、7.1、9.5 节引用本节的原因。

**量化台阶**：

```text
分辨率        2π / 4096 = 1.534e-3 rad/LSB
差分窗口      1 ms（AS5600 更新周期）
速度量化      1.534e-3 / 1e-3 = 1.534 rad/s per LSB
速度参考满量程 ±10 rad/s
→ 单个 LSB = 满量程的 15.3%
```

**传到电流指令上**：速度 PI 的 `P = 0.1` 时，一个 LSB 的角度抖动直接产生 `0.1 × 1.534 = 0.153 A` 的 `iq_ref` 跳变，而 `iq_ref` 上限只有 0.53 A —— **28.9% 满量程的指令抖动**。这不是「参数没调好」，是反馈通道的信息量不够。

**dt 本身也是量化的**：`AS5600_GetVelocity()` 用 `last_success_tick` 之差计算 dt，时基是 `HAL_GetTick()`，分辨率 1 ms。TIM2（1 kHz）与 SysTick（1 kHz）是两个独立时基，相位必然漂移，加上软件 I²C 210~235 µs 的执行抖动，相邻两次 tick 差会在 0/1/2 之间跳变：

- 差为 1：dt 正确；
- 差为 2：角度增量跨了两拍，dt 记 2 ms，速度值正确但延迟翻倍；
- 差为 0：函数直接 `return 0.0f`，**速度反馈周期性掉零**，且 `velocity_previous_*` 不更新，下一拍的增量跨两拍而 dt 记 1 ms，**速度读数翻倍**。

即 dt 误差可达 ±100%，且失真是有偏的。

**为什么一阶低通不够**：现有 `Tf = 0.01 s`（截止 15.9 Hz）对量化台阶只能做幅度平滑，无法恢复被量化掉的信息，同时引入约 10 ms 相位滞后，把速度环带宽压到 10 Hz 以下。而位置环还要在速度环之上再降 5 倍，就只剩 2 Hz——位置环实际上被挤没了。

**加长差分窗口的代价**：窗口拉到 N ms 可把量化降到 `1.534/N` rad/s，但引入 N/2 ms 群延迟。N = 16 时量化 0.096 rad/s（满量程 0.96%，可接受），群延迟 8 ms，速度环带宽上限仍然只有约 10 Hz。**这条路能让速度环勉强跑起来，但撑不住再串一级位置环。**

**结论**：速度环、位置环模式下必须使用第 22.3 节的观测器。第 7.1 节原有的「不增加角度预测器、速度观测器」约束与「实现速度环、位置环」的目标不可兼得，本次选择保留后者。

### 22.3 角度/速度跟踪观测器

二阶跟踪观测器（PLL 型）。**15 kHz 预测、1 kHz 修正**，这是它同时解决三个问题的原因：速度量化、dt 抖动、电角度 1 kHz 阶梯。

**状态**：

```text
theta_hat      观测机械角，连续累计（多圈），单位 rad
omega_hat      观测机械角速度，单位 rad/s
last_correct_tick  最近一次修正时间
```

**预测（ADC 注入 ISR 内，Ts_f = 1/15000 s）**：

```text
theta_hat += omega_hat * Ts_f
theta_el   = normalize(dir * pp * theta_hat - zero_electric_angle)
```

**修正（1 ms 前台任务，`AS5600_Update()` 成功后，Ts_s = 1e-3 s）**：

```text
e = wrap_pi(theta_meas_single_turn - wrap_2pi(theta_hat))   /* 归一化到 (-pi, pi] */
theta_hat += K1 * e
omega_hat += K2 * e
last_correct_tick = now
```

**增益**（由自然频率 `ω_n` 与阻尼 `ζ` 给出）：

```text
K1 = 2 * zeta * omega_n * Ts_s
K2 = omega_n^2 * Ts_s

起始设计值：omega_n = 2*pi*40 rad/s，zeta = 0.9，Ts_s = 1e-3
→ K1 = 0.452，K2 = 63.2
```

**四条必须写死的规则**：

1. **多圈计数由观测器维护**。修正量 `e` 用单圈误差经 `wrap_pi` 归一化，`theta_hat` 本身连续累计。这样跨 0/4095 边界不需要额外判定，AS5600 侧的 `rotation_offset` 逻辑只用于监控。
2. **丢拍只跳过修正，不跳过预测**。`AS5600_Update()` 失败时观测器按 `omega_hat` 继续外推。连续丢拍导致 `now - last_correct_tick > sensor_max_age_ms`（3~5 ms）时按第 12.1 节关断——外推能力不是放宽该阈值的理由。
3. **跨上下文共享必须加临界区**。`theta_hat`/`omega_hat` 被 15 kHz ISR 和 1 ms 前台同时访问，两个 `float` 不构成原子的一致快照。修正侧沿用现有 `FOC_UpdateCachedSensorAngle()` 的模式：`__disable_irq()` → 清有效位 → 写 → `__DMB()` → 置有效位。
4. **初始化与复位**。ALIGN 结束、进入 RUN 之前：`theta_hat = 实测机械角`，`omega_hat = 0`。任何故障关断后同样复位，避免残留速度估计在下次使能时被当作真实运动。

**顺带解决的电角度阶梯问题**：当前电流环 15 kHz 使用 1 ms 更新一次的 `cached_angle_el`，角度是 15 级的阶梯。`pp = 11`、机械速度 10 rad/s 时 `ω_e = 110 rad/s`，一个 1 ms 窗口内电角度走过 6.3°，误差从 0 线性涨到 6.3°。转矩损失只有 0.6%（可忽略），但 **d 轴交叉耦合是 `|i|·sin(6.3°) = 11%`**，表现为 id 上 1 kHz、幅值约 ±5.5%|i| 的纹波，d 轴 PI 会持续与之对抗。15 kHz 预测把这项残差降到 `ω̂` 估计误差乘 66.7 µs 的量级，基本消除。

**验收**：`omega_hat` 在恒速手动转动下的抖动 ≤ 0.15 rad/s（速度参考满量程 1.5%）；阶跃改变转速时 `omega_hat` 的上升时间与设计的 `ω_n` 一致。若实测抖动超标，先降 `ω_n` 再考虑其他手段。

### 22.4 AS5600 寄存器配置

当前 `as5600.c` 全文没有任何 `IIC_Write_*` 调用，CONF 寄存器（0x07/0x08）保持上电默认值，其中**慢速滤波 SF 处于最慢档**。AS5600 的慢速滤波档位在「阶跃响应延迟」和「输出噪声」之间折衷，最慢档的延迟对 1 kHz 速度环是显著的相位滞后。

> ⚠ **本节的具体数值需按 AMS AS5600 datasheet 复核后填入**：AS5600 datasheet路径： "E:\0001_LCWork\datasheet\as5600.pdf"。按记忆，SF 默认为 16x（阶跃延迟约 2.2 ms），可选 8x / 4x / 2x，2x 约 0.286 ms、RMS 噪声约 0.043°；0.043° ≈ 0.75 mrad，小于一个 LSB（1.534 mrad），因此提速到 2x 的噪声代价被量化噪声淹没。**若 datasheet 与此不符，以 datasheet 为准。**

要做的事：

1. `AS5600_Init()` 中读回 CONF，写入选定的 SF/FTH 组合，再读回校验（与 DRV8301 的 `WriteRegVerified` 同样的模式）；
2. CONF 是易失寄存器，每次上电写入，不使用 `BURN_SETTING`，不消耗 ZMCO 烧写次数；
3. 写失败视为初始化失败，进入 FAULT；
4. 台架用示波器或调试变量对比配置前后的阶跃响应，确认延迟改善量与 datasheet 一致。

顺带确认两件事：初始化只检查了 MD（磁体存在）位，未检查 ML/MH（磁场过弱/过强），建议补上；`AS5600_Update()` 运行期完全不复检 STATUS，磁体掉落无法发现，放到 200 ms 低频任务里查一次即可（见 P1-10）。

### 22.5 保护能力的真实边界

这一节的存在意义是：**不要以为有 DRV8301 就有硬件过流保护。**

**① DRV8301 的 VDS 过流对本电机等于不存在。**

```text
CTRL1 配置 OC_ADJ_SET = 0.250 V（VDS 门限）
功率管 CSD18533Q5A，RDS(on) 约 3.5 mΩ @ VGS ≈ 11 V
触发电流 = 0.250 V / 3.5 mΩ ≈ 70 A
```

即使调到 DRV8301 的最小档 0.060 V，触发点也在 17 A。而本电机工作电流 0.3~0.5 A、软件限值 1.0 A。硬件 OC 只能防止桥臂直通级别的灾难，对绕组过流没有任何作用。

**② nFAULT / NOCTW 没有接到 MCU。**

原理图上这两个信号只经 U10（SN74AHC1G08 与门）驱动 Q1/LED1，H1 连接器只有 `DC_CAL / EN_GATE / SPI_CS / SPI_MOSI / SPI_MISO / SPI_CLK / +3.3V`。因此：

- 没有硬件快速故障通路，MCU 发现 DRV8301 故障的唯一途径是 SPI 轮询，当前周期 200 ms；
- TIM1 BKIN 无硬件连线，`BreakState = DISABLE` 与硬件一致，**不存在硬件刹车**；
- 第 11.3 节「不增加新的硬件 Break 连接或修改 PCB」的选择是合理的，但后果必须写明：**故障发现延迟上界 = 200 ms**。

**③ 结论：15 kHz 软件过流是唯一有效的绕组保护。**

```text
最坏响应时间 = 1 个 PWM 周期 = 66.7 µs
di/dt 上界 ≈ Vdc / L = 24 V / 1 mH = 24 A/ms
一个周期内电流可涨 ≈ 1.6 A
```

由此得出三条硬性要求，必须写进验收：

- `FOC_CURRENT_ABS_LIMIT_A` 的选取必须为这 1.6 A 的检测盲区留裕量，不能贴着电机额定值设；
- 在 P0 全部修复并完成 CH4 窗口实测之前，**只允许使用带限流的实验电源**，限流值设在电机峰值允许电流以内；
- ADC 注入 ISR 的最坏执行时间必须实测（DWT 埋点 `adc_injected_callback_max_cycles` 已存在），因为 ISR 超时会直接延长这个盲区。目标 ≤ 20 µs（周期占用 30%）。

### 22.6 可选增强（不属于速度环前置条件）

**① ADC1 + ADC2 注入双同步**。PA3 = ADC1_IN3、PA4 = ADC2_IN4，F407 的 ADC2 当前空闲，无需改硬件。两相真正同一时刻采样，时差从 1.286 µs 降到 0，序列耗时降到 216 tick。代价是要改 CubeMX、重新生成 `adc.c`、改 ISR 取值方式。P0-1 修复后 1.286 µs 的时差（周期的 1.9%）已可接受，本项排在后面。

**② DRV8301 电流放大增益 10 → 40**。当前链路：

```text
分流 0.010 Ω × 增益 10 V/V = 0.1 V/A
分辨率 = 3.3 V / 4096 / 0.1 = 8.06 mA/LSB
量程   = ±1.65 V / 0.1 = ±16.5 A
```

工作电流 0.53 A 只占量程的 3.2%，满量程指令只有 66 个码。改 `DRV8301_CR2_GAIN_40`：

```text
0.010 Ω × 40 = 0.4 V/A
分辨率 = 2.01 mA/LSB（提升 4 倍）
量程   = ±4.13 A（对齐电流限 1.0 A、过流限 1.0 A 均在量程内）
```

这是同时给电流环和速度环降噪最省事的一步——速度环的噪声有一部分是电流环噪声传上去的。**配套改动**：`CURRENT_GAIN` 10.0f → 40.0f；`FOC_CURRENT_OFFSET_MAX_SPAN_COUNTS` 由 64 放宽约 4 倍（否则 DC_CAL 校准会直接判失败）；重做 offset 标定与符号验证。

**③ 母线电压合理性监控**。原理图上没有独立的 PVDD 分压，但三相端电压分压（÷7.974，365 Hz 低通）在共模居中调制下满足：

```text
u_a + u_b + u_c = 3 * Vdc / 2   ->   Vdc ≈ (2/3) * (V_U + V_V + V_W)
```

仅在 MOE 使能、且 `FOC_SetPwm()` 走「共模居中」分支（`span ≤ allowed_span`）时成立；走「等比压缩」分支时不成立。因此**只能用作监控**（偏离标称 24 V ±20% 报警），不得进入控制。第 10 节排除「母线电压估算」的立场不变，但增加这条监控是有价值的：当前 `FOC_GetEffectiveVoltageLimit()` 用的是硬编码 24.0 V，母线跌落时电压限幅不跟随，至少要能发现。

### 22.7 1 ms 前台任务的执行顺序

固定为（速度环/位置环模式）：

```text
TIM2 UEV -> 置 flag（ISR 内只做这一件事）

主循环检测到 flag:
  1. 临界区内取观测器快照 theta_hat / omega_hat
  2. 位置环  -> speed_ref            （USE_POSITION_LOOP）
  3. 速度环  -> iq_ref -> 写入        （USE_SPEED_LOOP）
  4. AS5600_Update()                 阻塞 210~235 µs
  5. 成功 -> 临界区内做观测器修正
     失败 -> error_count++，不修正、不改 last_correct_tick
  6. 检查 now - last_correct_tick > sensor_max_age_ms -> 关断
  7. 检查 flag 是否在步骤 1~6 期间被重新置位 -> 丢拍计数 + 上报
```

三个要点：

- **外环在 tick 开头、`AS5600_Update()` 之前**。软件 I²C 的阻塞时长和失败重试都会污染外环执行时刻；把外环钉在 tick 开头，`PID_SetFixedDt(1 ms)` 这个固定值才成立。用上一拍的观测器输出不损失精度——观测器在 15 kHz 预测，快照永远是新鲜的。
- **丢拍必须可见**。现有 flag 是置位型，主循环超过 1 ms 时 tick 被静默丢弃。步骤 7 至少要能统计出来，否则外环 dt 失真无法诊断。
- **禁止在本任务内输出日志**（P1-5）。115200 baud 下一条 128 字节日志 11.1 ms，直接打穿 11 个 tick。

### 22.8 实施偏差记录（2026-08-11）

以下六处与本节/第 23 节原文不同，都是实施中发现原方案有缺口后做的修正，后续复审以本小节为准。

**① `theta_hat` 拆成「单圈角 + 整圈计数」，而不是 float 连续累计。**

22.3 规定 `theta_hat` 多圈连续累计。float32 在 628 rad（100 转）处的 eps 约 5e-5 rad，在 6280 rad（1000 转）处约 5e-4 rad，而 10 rad/s 下单个预测拍的增量只有 6.7e-4 rad——**累计到千转量级时预测增量已经开始被舍入吃掉**。实现改为 `obs_theta_hat` 归一化在 `[0, 2π)`、`obs_turns` 单独用 `int32_t` 记整圈，位置反馈由 `FOC_ObserverSnapshot()` 重新组装。跨 0/4095 边界仍然不需要传感器侧判定，与 22.3 规则 1 的意图一致。

**② 15 kHz 预测路径不调用 `fmodf`。**

`_normalizeAngle()` 用 `fmodf`，在 15 kHz ISR 上是不必要的开销。电角度改为按 `dir·pp·ω̂·Ts_f` 增量推进，只在跨越 `[0, 2π)` 时才回退到 `_normalizeAngle()`（10 rad/s 机械速度下约 17 次/秒），并且每 1 ms 修正时用精确式重新锚定，累计误差不会累积。观测速度增加了 `±200 rad/s` 的合理性钳位，防止异常值一次跳过多圈把 `obs_turns` 记错。

**③ P1-7 取 23.4 的第一种修法：限幅只在一处发生。**

`pid.c` 新增 `external_output_limit` 模式——置位后 `PID_Calc()` 不再做分轴方形限幅（`limit` 仍然约束积分器本身），电压限幅全部交给 `FOC_SetVoltageDqWithTrig()` 的矢量圆限幅；圆限幅削掉的量由 `PID_ApplyExternalClip()` 回传给条件积分判据。同一个函数也用于 23.4 第 4 条：`FOC_T` 导出 `voltage_saturated` / `voltage_saturation_sign`，速度 PI 在电流环电压饱和且误差同向时冻结积分。

**④ 速度环取消一阶低通滤波器。**

22.2 已论证一阶低通对量化台阶无效且引入约 10 ms 相位滞后。观测器投入后再串一级低通，速度环带宽会被压到 23.1 规定的 20 Hz 以下，两者不可兼得。因此 `Foc_VelocityLoop()` 直接使用观测速度，`velocity_filter` 及 `LOWPASS_FILTER_Calc()` 一并删除。低通滤波器只剩监控通道在用（固定 dt）。

**⑤ 就绪日志必须打在进入 RUN 之前。**

P0-2 把 `sensor_max_age_ms` 从 50 ms 收到 5 ms 之后，原来「先置 `bldc_state = RUN`、再打 `BLDC ... ready` 日志」的顺序会立刻失效：日志阻塞约 11 ms，第一拍电流环就会判传感器超龄并关断。实施中把日志提到置 RUN 之前，并在置 RUN 前补一次 `FOC_HAL_UpdateSensor()` 刷新角度缓存。**任何在 RUN 期间新增的阻塞调用都要按 5 ms 这个预算重新核算。**

**⑥ 丢拍只计数不打日志，且改用真实时基判定。**

22.7 步骤 7 写的是「检查 flag 是否在步骤 1~6 期间被重新置位」，这只能发现 1 ms 任务体自身超时，发现不了 200 ms 任务（SPI + I²C + 可能的故障日志）造成的丢拍。实现改为在每次进入 1 ms 任务时比较 `HAL_GetTick()` 差值，`> 1` 即按差值累加 `outer_tick_overrun_count`，覆盖全部丢拍来源。

「上报」改为**只做调试变量、不打日志**：在 200 ms 任务里打这条日志本身就要阻塞 11 ms、再丢 11 拍，会让计数继续增长从而触发下一条日志，形成自激。`outer_tick_overrun_count` / `sensor_read_error_count` 与已有的 `adc_injected_callback_max_cycles` 一样由调试器读取。

## 23. 三级串级控制设计（2026-08-11 新增）

第 20 节定义了「有哪些环、接口是什么」，本节定义「这些环怎么才能一起稳定工作」。

### 23.1 带宽分配

串级控制的核心约束是相邻两级的带宽必须分离。本项目位置环与速度环**同拍执行、无分频**（第 20.2 节），因此带宽分离**只能靠参数实现**，必须显式写死：

| 环节           | 采样周期                  | 起始设计带宽      | 上限约束                                                |
| -------------- | ------------------------- | ----------------- | ------------------------------------------------------- |
| 观测器`ω_n` | 修正 1 ms / 预测 66.7 µs | 40 Hz（ζ = 0.9） | 越高量化噪声透传越多；须 ≥ 2 × 速度环带宽             |
| 电流环`f_ci` | 66.7 µs                  | 600 Hz            | ≤`f_s,cur / 20` = 750 Hz                             |
| 速度环`f_cv` | 1 ms                      | 20 Hz             | ≤`f_ci / 10`；≤ `ω_n / 2`；≤ `f_s,outer / 10` |
| 位置环`f_cp` | 1 ms                      | 4 Hz              | ≤`f_cv / 5`                                          |

电流环上限的依据：计算 + PWM 更新引入约 1.5 拍延迟 = 100 µs，在 600 Hz 处贡献 `360° × 600 × 100e-6 = 21.6°` 相位滞后，尚可接受；再往上相位裕度迅速恶化。

速度环上限由三条同时约束，当前最紧的是观测器带宽。**如果实测证明观测器噪声允许，先提 `ω_n` 到 60~80 Hz，速度环才有条件提到 30~40 Hz，位置环随之到 6~8 Hz。** 顺序不能倒过来。

### 23.2 各环整定

放弃「先加 P 再加小 I」的试凑，改用解析式给初值，再在台架上微调。**前提是先实测电机参数**——这些正是第 19 节列出但至今空白的量。

**电流环**（零极点对消，被控对象 `1/(Ls+R)`）：

```text
Kp = omega_ci * L
Ki = omega_ci * R          （PID 结构为并联式，Ki 单位 V/(A·s)）
omega_ci = 2*pi*600 = 3770 rad/s
```

对当前参数的反推与结论：

```text
现值 P = 4      -> 隐含 L = 4 / 3770 = 1.06 mH
现值 I = 2000   -> 隐含 R = 2000 / 3770 = 0.53 Ω
第 6.3 节实测等效相阻 3.2~4.0 Ω
-> 按 R = 3.5 Ω，Ki 应在 13200 附近，现值偏小 6.6 倍
```

积分零点落在 500 rad/s，而被控对象极点在 `R/L ≈ 3300 rad/s`，两者差 6.6 倍意味着**积分补偿严重滞后于电气时间常数**，表现为电流跟踪拖尾和与负载成比例的稳态误差。修正的前提是先用 LCR 表或阶跃法实测 R、L，不能直接按上式套用推断值。

**速度环**（被控对象 `Kt/(Js+B) ≈ Kt/(Js)`）：

```text
Kp_v = J * omega_cv / Kt
Ki_v = Kp_v * omega_cv / 4        （积分零点置于穿越频率 1/4 处）
Kt   = 1.5 * pp * lambda_m        （与第 12.2 节的幅值不变 Clarke 一致）
```

`lambda_m` 由空载相反电势幅值除以 `pp * ω_m` 得到；`J` 由加速度阶跃法辨识（给定 `iq` 阶跃，测 `dω/dt`）。**当前 `I = 0`，速度环是纯 P**，必然存在与负载转矩成正比的稳态速度误差——这是设计缺口不是保守选择，整定时必须补上 I 项。

**位置环**（P 型，输出直接是 `rad/s`）：

```text
Kp_p = omega_cp
现值 Kp_p = 2.0 -> omega_cp = 2 rad/s = 0.32 Hz
目标 f_cp = 4 Hz -> Kp_p = 2*pi*4 = 25
```

位置环起始用纯 P。若静态位置误差（重力、摩擦）不可接受再加小 I，且必须配独立的积分限幅——位置环的 I 是三级里最容易积出危险指令的一项。**不加 D**：D 项作用于位置误差等价于速度反馈，而速度环已经在做这件事，重复引入只会放大观测器噪声。

### 23.3 调度时序

见第 22.7 节。补充电流环侧的一条约束：ADC 在周期 N 的峰值附近采样 → ISR 计算 → 写 CCR → 在下一个 UEV（周期 N 的谷值）生效 → 作用于周期 N+1。**总延迟约 1.5 个 PWM 周期 = 100 µs**，这是第 23.1 节电流环带宽上限的来源，整定时不能假装它不存在。

### 23.4 串级抗饱和

每一级的限幅都必须与上一级的积分行为联动，否则串级一定会 windup。四条规则：

1. **每级 PID 使用条件积分**（`pid.c` 已实现）：输出被限幅且误差与限幅方向同向时，积分冻结在上一拍的值。第 12.4 节选择冻结而非回算的理由成立，保留。
2. **速度 PI 的输出限幅必须等于 `FOC_IQ_REF_LIMIT`**。这样「iq 指令饱和」与「速度 PI 输出饱和」是同一件事，条件积分自动覆盖。当前设计已满足，不要在两处写不同的数。
3. **位置环输出限幅必须等于 `speed_ref` 的限幅**，理由同上。
4. **电流环的电压饱和必须回传给速度环**——这是当前缺失的一环。当 dq 电压饱和时，实际 `iq` 跟不上 `iq_ref`（高速、母线跌落、堵转），而速度 PI 看到的是「指令没饱和」，会继续积分。做法：电流环导出 `voltage_saturated` 标志（圆限幅生效即置位），速度 PI 在该标志置位且误差同向时冻结积分。

**另有一个电流环内部的抗饱和缺陷**（P1-7）：现在是两级串联限幅——PID 各轴先方形限到 ±4 V，`FOC_SetVoltageDqWithTrig()` 再做矢量圆限幅。PID 的条件积分只知道自己那个方框，**圆限幅削掉的部分不会触发积分冻结**，圆限幅路径存在积分饱和。两种修法任选：

- 取消 PID 内部的方形限幅（把 `limit` 放大到不起作用），限幅统一在圆限幅处做，并把削幅量回传给两个 PID 的条件积分判据；
- 或保留方形限幅，但把圆限幅后的实际 `ud`/`uq` 回写为 PID 的 `prev_output`。

第一种更干净：**限幅只在一处发生**，也符合矢量圆限幅保持电压矢量方向的初衷（先分轴削幅会先扭曲 d/q 比例，再圆限幅已无法恢复）。

### 23.5 方向约定

**这是最容易一次跑飞的地方，必须写成规范而不是靠代码里恰好乘对了。**

定义：**正方向 = 施加正 `iq` 时转子实际旋转的方向**。`sensor_direction`（代码中 `foc.dir`）由第 8 节的对齐流程确定，取值 `+1` 或 `−1`。

由此推出四条强制约束：

```text
theta_el      = normalize(dir * pp * theta_mech - zero_electric_angle)
速度反馈       = dir * omega_hat
位置反馈       = dir * theta_hat            （多圈累计）
位置参考       与位置反馈同坐标系，进入闭环时初始化为当前位置反馈
```

**任何一处漏乘 `dir`，在 `dir = −1` 的装配下位置环就变成正反馈，直接跑飞。** 当前代码在四处都乘对了，但文档从未规定这条——第 6.2 节只定义了电角度公式，第 20.3 节说 `position_ref` 单位是「累计机械角 rad」，没说是否 `dir` 修正过。这类「靠实现恰好正确」的约定，下一次重构就会丢。

**验收方式**：把 AS5600 磁体翻面安装（或临时强制 `dir = −1`）重跑一遍，位置环必须仍然收敛。只在 `dir = +1` 下验证等于没验证。

### 23.6 模式切换与无扰

- 三个宏的合法组合与依赖校验沿用第 20.1 节，`#error` 已实现；
- 进入 RUN 之前：复位全部已启用环路的 PID、观测器、低通滤波器状态。ALIGN 阶段的电压注入会在各级积分器里留下残值，不清会在闭环瞬间释放；
- 位置环模式下 `position_ref` 初始化为当前位置反馈（第 20.4 节已规定），确保闭环瞬间误差为 0；
- 速度环模式下 `speed_ref` 初始化为 `0`（P1-3）；
- 故障锁存后无恢复路径，只能复位重启，这一点要写进对外接口文档。
