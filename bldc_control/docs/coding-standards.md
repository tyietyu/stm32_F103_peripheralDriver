# Coding Standards

本文件细化入口规则中的编码规范。生成、修改、重构或评审代码时按需读取。

## 通用编码规则

- 代码注释、文档和提交说明优先中文，专有名词和 API 名称保持原文；文件统一使用 UTF-8 无 BOM 和 LF。
- 保持现有架构、接口、技术选型、命名、格式和错误处理风格；相似功能使用一致的实现方式。
- 不覆盖、回退或夹带用户已有改动，不顺手优化无关代码；仅移除因本次变更而失效的代码。
- 优先使用现有依赖、标准库和原生能力；仅在确有复用、独立业务语义或能显著降低复杂度时提取模块，不为未来假设提前抽象。
- 保持现有接口兼容；新增接口仅返回业务所需字段。
- 通过现有架构与框架的生命周期、扩展点和控制边界接入，不绕过框架钩子或横切行为。
- 关键逻辑、接口约定、复杂函数和非显而易见的决策必须添加简洁中文注释，避免无意义注释。
- 可恢复错误就近处理并记录必要上下文；不可恢复错误快速失败并向上抛出；禁止空 `catch`、吞异常或伪成功。
- 日志只记录必要的入参摘要、分支决策、状态变化和异常；不记录敏感信息或制造高频噪声。
- 若代码变更导致文档、配置、示例或类型定义过时，应同步更新；跨层规则变更须同步维护相关校验、类型、接口契约、权限、字段展示和文案。
