# Risk And Tools

本文件细化入口规则中的范围与授权、风险控制、联网、工具和 Git 规则。涉及高风险操作、外部资料、第三方库或工具选择时按需读取。

## 范围、授权与风险控制

- 用户明确要求修改、修复、实现、创建或删除时，已授权范围内的可逆本地变更直接实施和验证，无需再次等待确认；仅要求计划、分析、解释、诊断、Review 或状态时，只读检查，不修改环境。
- 新增或升级依赖的实际安装、数据库写入或迁移执行、真实环境配置、权限或环境变量变更、提交、推送、合并、发布、部署、删除或覆盖大量文件及其他高风险或不可逆操作，执行前须说明影响并取得明确授权。已有授权覆盖同一操作和范围时不重复询问，工具强制审批除外。
- 在上述执行步骤前，先完成已授权范围内可供审阅的本地代码、配置草稿、SQL 脚本和必要验证；准备文件不等于授权在真实环境执行。
- 跨模块、公共接口或数据模型改动先说明方案、影响和验证方式；大范围重构或架构调整补充替代方案和回滚方式。已授权的可逆本地修改继续实施，范围内的常规实现调整自行处理。
- 扩大范围、方案变化显著影响兼容性、数据、安全或成本，或存在尚未授权的重大兼容性变化、真实数据影响及无法从需求确定的关键选择时，先确认受影响部分。
- 低风险、可逆且不改变目标的不确定事项可明确假设后继续；关键选择会显著影响结果、兼容性或风险时先询问。等待期间继续不依赖该答案的已授权工作。
- 同一问题连续多次修复失败时，停止堆补丁，重新分析根因并尝试不同路径；需要回退时仅处理本次引入的改动，不覆盖用户已有工作。
- 对安全、隐私、合规相关内容采取最小暴露原则，不输出或写入敏感信息。

## 联网与外部资料

- 用户明确禁止联网时不联网。纯本地修改优先使用仓库信息；仅在判断依赖最新状态、版本差异、标准、安全公告、价格、政策或必要信息缺失时查询权威来源。
- 库或框架问题仅在仓库不足以确认所需 API 或版本行为时查询外部文档；仅提到框架名不构成联网理由。用户提供准确官方链接时直接读取，内容不足时再搜索。
- 优先官方文档、开发者指南、OpenAPI 规范、SDK 文档、标准、项目仓库和发行说明，避免内容农场或凭记忆猜测接口契约。
- 第三方集成需核实端点、参数、认证、权限、限流和错误格式等实际依赖的契约，不猜测 SDK 方法名或版本行为。
- 使用外部信息时保留关键来源，区分事实、推断和建议；网络或工具不可用时给出保守答案并标注不确定性。

## 工具选择

- 遵循最小必要、串行优先、可追溯原则；默认在主 Agent 内完成工作，sub-agent 的授权与平台限制以入口文件为准。
- 本地代码理解、修改和 Review 优先使用 `rg`、源码阅读及项目内验证；需要交互或必须保持原生行为时直接执行相应命令。
- 确需查询外部文档时，Context7 可用且适用则优先使用，先确认库与版本再聚焦 topic。
- 网页检索用于官方入口、最新信息和交叉验证；Serena 可用于必要的项目内语义检索、跨文件聚合与只读分析。
- 复杂架构或跨文件调用链分析可优先使用目标仓库已有的 CodeGraph，并显式传入 `projectPath`；简单定位使用 `rg`。索引结果必须回到当前源码验证，不主动初始化索引。
- 工具输出与当前源码、配置或测试冲突时，以项目实际状态为准。
- 工具失败时降级到替代来源；全部失败时说明限制和保守判断。使用外部工具时，在答复末尾简要说明工具、目的、输入摘要、关键参数、来源和失败重试情况。

## Shell 与 Git

- 先获取摘要，再按需展开上下文；避免无过滤的大范围搜索、日志、完整 diff 和高成本命令。
- 暂存或提交前确认只包含本次目标文件，不包含本地环境文件或用户已有改动。
- 未经用户明确要求，不创建提交、不推送、不合并、不发布或部署。
- Git commit message 使用中文，严禁添加 `Co-Authored-By`、Claude 贡献者或任何 AI 署名标识。
