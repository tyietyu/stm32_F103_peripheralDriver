# Testing And Validation

本文件细化嵌入式软硬件的验证与交付要求。涉及固件、驱动、通信协议、工程配置、硬件设计、板级调试或交付说明时按需读取。

## 验证范围

- 根据改动范围和风险执行最小充分验证，不把全量构建、全量测试或完整板级联调作为普通改动的默认步骤。
- 固件逻辑或数据流变化检查受影响的入口、核心逻辑、边界、异常和出口；文档或注释修改不扩展为完整固件链路审查。
- 按改动影响优先覆盖状态机、通信协议、数据转换、时序、中断与 RTOS 并发、内存边界、异常恢复和软硬件接口，不扩大到无关模块。
- 修复缺陷或新增校验时，先建立针对性复现或非法输入测试，再验证修复；重构时确认相关测试在改动前后均通过。
- 默认只对本次改动文件执行快速静态检查，并执行低成本差异检查；修改工程配置、链接脚本或硬件配置时，补充对应的结构、地址布局或参数一致性检查。没有相关改动时不运行无关检查。
- 最后一次检查后若只修改了文档、注释或格式，不重复执行高成本验证。
- Mock 只覆盖不可控的硬件或外部设备依赖，尽量保留真实的固件逻辑与协议处理。

## 固件构建与硬件验证边界

- 构建前确认芯片型号、板卡版本、工具链、工程入口和目标配置；优先使用项目已有工具链与构建脚本，不擅自安装或升级依赖。
- 固件代码或配置变更按风险选择受影响目标的增量构建、静态检查、主机侧单测或协议样例回放，不要求全部执行；涉及启动流程、链接布局、编译选项或跨模块接口时，补充相关目标的构建与链接检查。
- 涉及引脚、时钟、电源、外设接口或通信时序时，核对对应板卡的原理图、器件资料和现有配置；静态检查无法覆盖的风险再安排针对性的板级验证。
- 上板验证仅覆盖受影响的功能与必要回归，记录板卡版本、供电与连接方式、固件版本、测试步骤和实际现象；按需保留串口日志、协议抓包或测量波形，不做无关设备巡检。
- 原理图、PCB 布局及硬件连接图等可视化产物，优先使用现有工具进行渲染或截图级核对；缺少工具时只声明已完成的结构检查及残余风险，不断言视觉检查通过。
- 验证需求不自动授权固件烧录、器件擦除、写入 OTP / Option Bytes、修改量产参数或可能驱动执行器的测试；执行前说明影响并确认已有授权覆盖该操作与设备，授权不足时先取得明确授权，其他风险边界遵循 `risk-and-tools.md`。

## 完成与交付

- 实现用户要求、完成最小充分验证并修复本次改动造成的问题后交付，不追加无关重构或美化。
- 声称验证通过前必须实际执行对应命令或测试步骤并确认结果；交付时简要说明修改内容、实际执行的验证和直接相关的残余风险。
- 缺少工具链、硬件或测量设备时，说明受限的验证项，区分静态检查、构建通过与上板验证，不将编译通过等同于硬件功能或时序验证通过；无需罗列不适用的检查项。
